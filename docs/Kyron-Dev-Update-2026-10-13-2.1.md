# Kyron 2.1 — Material 3 UI overhaul (Wave UX-1, board task K-12)

**Date:** Oct 13, 2026 · **Build:** versionCode 3 / versionName "2.1", package com.kyronapp.kyron, debug-signed (same key as 2.0/LF builds — installs as an update)
**APK:** Kyron-2.1.apk · 9,963,891 bytes · md5 353c2648c8a9e6e6560283f1862f8f43 (delivered copy verified identical to the build output)
**Trigger:** Mark's product-owner verdict on the LF build (Oct 13, 5:39 PM CDT): "the icons and alerts selection is terrible. App navigation and user friendliness sucks — fix it." The six acceptance gates issued with that verdict are the spec for this wave; the gate-by-gate report is at the end.

## What changed

**Design system.** Full Material 3 (Theme.Material3.Light.NoActionBar) with a Kyron palette built on the existing brand greens. Added Material Components 1.12.0 + CardView 1.0.0 + CoordinatorLayout 1.2.0 + ConstraintLayout 2.1.4 + ViewPager2 + Transition + SwipeRefreshLayout + DynamicAnimation to the manual pipeline's dependency closure (POM-walking resolver; two styleable conflicts with AppCompat — SearchView, Carousel — resolved by dropping Material's unused copies from the unpacked AAR resources; neither widget is used).

**Icons (gate 1).** 24 hand-authored Material vector icons (search, map, star, star-outline, bell, place, my-location, directions, share, sync, back, close, check, edit, delete, warning, info, person, download, tune, chevrons). Every emoji functional icon is gone — verified by a full-tree scan of Kotlin + layouts (zero matches). The list-row favorite is now a 48dp ImageButton with a real star icon, state tint, and content descriptions ("Watch this place" / "Watching this place").

**Navigation (gate 3).** Labeled Material BottomNavigationView (Browse / Map / Favorites / Alerts) replaces the emoji text tabs. MainActivity keeps LF-4's keep-alive fragment architecture — tab switches preserve each tab's full state (verified pattern: Browse query survives a tab round-trip by design, since fragments are never destroyed). Detail is an activity over the preserved tabs, so Back returns to the exact prior list/map state. The screen title moved into a MaterialToolbar; the LF-4 region chip is now a proper MaterialButton with a dropdown icon in that toolbar. Favorites' empty state has a "Browse restaurants" button that switches tabs (no dead ends).

**Browse.** Material outlined search field ("Search restaurants, cities, ZIP codes"), filter chips (All scores / Below 85 / 85–94 / 95+) replacing the button row, county + sort as exposed-dropdown menus (defaults populated immediately — no empty-dropdown window), restaurant results as Material cards, pull-to-refresh wired to sync (spinner tied to the follow-up query completing), designed empty state (icon + guidance + "Clear search and filters"), and a dismissible first-run guidance card whose text matches the real UI. All LF-3/LF-4 query logic is untouched: SQLite/FTS search, ExploreState shared query with the Map, region scoping, and the disposition-region behavior (band chips + score sorts hidden where the jurisdiction publishes outcomes, not scores).

**Detail.** MaterialToolbar with a real back arrow; header/actions/why/violations/history are Material cards; actions are Watch (star icon, state-aware), Directions, and a new Share (plain-text summary via the system chooser). History is a single-select ChipGroup. Watch note no longer uses emoji. Disposition (Florida-style) rendering preserved verbatim from LF-4 — native result, no invented score, official-record link.

**Favorites.** New real layout (was programmatic): designed empty state with icon, plain-language guidance, and the Browse button; same card adapter as Browse.

**Alerts (gate 2) — the centerpiece.** The settings-form layout and the 67-checkbox county wall are deleted. The screen is now:
- **Alert inbox** card first — icon-coded alert cards (warning icon for low scores), tap opens the place.
- **"Alerts for my favorites"** rule card — one-tap MaterialSwitch quick-pick with plain-language description.
- **"Alerts for my areas"** rule card — the rule summarizes itself in one sentence ("Watching Jefferson and Mobile County · alert me when a new score drops below 85 · within 10 miles of Downtown Birmingham"), with a switch, **Edit area alerts**, and **Remove this rule** actions.
- The editor (collapsed until Edit): **searchable county picker dialog** — type-to-filter over all 67 Alabama counties, multi-select with a live "N of 67 counties selected" count, Select all / Clear all, changes applied only on Done (Cancel is a true cancel); **threshold as a plain-language Material Slider** — "Alert me when a new score drops below 85", number always visible; area center as preset **chips** + "Use my current location"; **radius slider** — "Watch places within 10 miles of my area center". An honest scope note remains: county checks run against Alabama sources; other states alert via favorites.
- Sync, profile, data sources, and backup export/import cards restyled to Material; all LF-2/LF-4 behavior preserved.

**Map.** Status line and place sheet are Material cards; sheet close is a real icon button; the Watch action is a MaterialButton with a star icon that flips to "Watching"; a FloatingActionButton (my-location icon, labeled) centers the map on the user's area. Pins, clustering, verified-locations-only, and the unified Explore filter are LF-3/LF-4 code, untouched except the badge-cache hardening below.

**Coverage (LF-4's state picker).** Restyled to the same language per gate 6: MaterialToolbar with an icon back button, outlined search field, Material location button, and state rows as Material cards with an "ACTIVE NOW" text badge (replacing the ● glyph) and tonal action buttons. All LF-4 logic — statuses, download/verify/install, rollback, remove, GPS-proposes-user-confirms — is byte-for-byte preserved apart from view construction.

**First-run guidance (gate 4).** The welcome dialog was rewritten to describe the actual new UI (bottom tabs, star-to-watch, region chip in the toolbar, Alerts tab) and states guest-first up front: "No sign-up needed — everything works right away."

## Pass-2 (independent bug-hunt, separate agent) — findings & dispositions

**Verdict as delivered to the builder: NO-SHIP** (2 P1 crashes, 2 P2 functional defects, 14 P3s, plus observations). Every P1/P2 and 12 of 14 P3s are fixed in the shipped build; the fixes were rebuilt and re-audited.

- **P1-1 Map tab crash (certain) — REAL, FIXED.** `MapFragment.sheet` was declared `LinearLayout?` while the redesigned layout declares `place_sheet` as a MaterialCardView; the inferred `findViewById<LinearLayout>` emitted a checkcast, so opening the Map tab would have thrown ClassCastException every time. Retyped to `View?` (the sheet is only used for visibility). Process lesson recorded: the builder's first findViewById↔layout pairing sweep only covered *explicitly typed* lookups and missed this inferred one; the sweep was redone over every typed field + assignment in all UI files and is clean.
- **P1-2 Alerts crash loop from imported radius (conditional) — REAL, FIXED.** Material's Slider validates discrete values: a fractional radius (e.g. 7.5 in a hand-edited or foreign backup — Backup imports ranges unchecked) would throw IllegalStateException on every Alerts open. bind() now normalizes stored values through the Prefs API before any control is set — threshold into 60..99 (also covering the pre-2.1 SeekBar's 100), radius into 1..50 **and rounded to whole miles** — and the slider assignments are clamped + rounded as a second line of defense. Noted for a future data-layer wave: Backup/UserStore should validate ranges at import.
- **P2-1 Browse pull-to-refresh lied — REAL, FIXED.** The spinner stopped only incidentally (when an unrelated in-flight query finished; a failed query could leave it spinning forever) and the list never re-queried after sync. `MainActivity.startSync` now takes a completion callback (fired in its finally, and immediately if a sync is already running); Browse passes one that re-runs the query, and the query itself stops the spinner in a finally, success or failure.
- **P2-2 Map applied the previous region's filters — REAL, FIXED.** ExploreState is region-blind: Browse county/band chosen in Alabama would filter Florida's map to empty (with a misleading "no places" status) until Browse was visited. MapFragment now detects a region change and resets county/band for its filtering until Browse republishes — matching Browse's own reset-on-region-change semantics.
- **P3s fixed:** unsaved profile name no longer wiped by re-binds (focus guard); threshold label/summary/slider/engine desync eliminated by the P1-2 normalization; Detail's Watch/Directions/Share buttons hide on the "Place not found" path instead of sitting dead; share text handles blank result/date; the map sheet now shows human source names ("Alabama Dept. of Public Health", not "adph") like Detail does; map status line tells the truth against the 400-pin cap ("Showing the first 400 of N… — zoom in"); Coverage's back button is a proper toolbar navigation icon (it previously rendered on the trailing side) and its action buttons use backgroundTintList so they keep Material shape/ripple; county picker's button now reads "Select all counties" (its scope); filter/preset/history chips raised to the 48dp touch-target gate via chipMinHeight; backup exports now record app version "2.1" (was hard-coded "2.0"); Favorites sorting puts no-score (disposition) places last instead of letting the −1 sentinel sort them first.
- **P3s not changed, with reasons:** Coverage list rebuild jank (LF-4 logic — 50 cards + a DB count per search keystroke; real, but a data-layer/perf change belongs to its own wave, filed to the backlog). The Map FAB keeps the my-location glyph with its accurate "Center the map on my area" description (it animates to the saved area center); noted, cosmetic.
- **Observations:** the orphaned `tab_selected.xml` drawable was deleted. `SyncEngine` embeds a ★ glyph in a notification title (worker code, LF-4's file set) — flagged to the main chat for the gate-1 sweep; this wave did not edit worker code. Also kept from the builder's own hardening pass: the map badge-icon cache now keys on every rendering input, dropdowns/guide-card state are re-synced deterministically on bind/resume.
- **Verified clean by pass-2 (no defects found):** guest-first/policy (no sign-up gates, no test-account references, no keys anywhere in src); icon set + labeled bottom nav; MainActivity navigation + syncingNav guard; Alerts bind() listener hygiene (no accumulation/loops); county picker bookkeeping (working set, true Cancel); Detail share intent + history-chip loop safety + NO_SCORE never rendered as a number in any reachable branch; Browse chip/dropdown mechanics; map data honesty (verified-locations-only pins, disposition clusters never invent a number); Coverage statuses/GPS-propose/rollback logic; removed-id references all gone.
